## 一、需求背景与价值

### 1.1 三层面板体系

| 面板 | 使用角色 | 视角 | 数据范围 | 定位 |
|------|---------|------|---------|------|
| **调解驾驶舱** | 系统管理员 | 全平台宏观监控 | 全平台所有法院/调解组织 | 监控驾驶舱（见《01》第三章） |
| **调解工作台·主管视角** | 带主管标识调解员 | 管辖法院执行视角 | 管辖法院全量案件 + 本人案件 | 工作台（见《01》第三章） |
| **调解工作台·调解员视角** | 普通调解员 | 个人执行视角 | 仅本人案件 | 个人工作台（见《01》第三章） |

**核心原则**：主管面板 = 调解员面板的全集 + 法院级数据模块（多法院切换、调解员效能排行、法院数据全景入口）。调解员面板不出现任何法院/他人汇总数据。

### 1.2 业务价值

- 将现有飞书多维表中的散点数据升级为分角色的可视化监控体系，解决"数据孤岛、监控不直观"问题；
- 异常优先呈现（超期、临期、待审批），缩短管理员/主管的异常发现与响应时间；
- 统一指标口径（成功率、平均调解时长、提成等），避免各端各算各账；
- 为后续 AI 报表（日/周/月报）提供同一套聚合口径。

### 1.3 与其他 PRD 的关系

- 面板模块结构对齐《01_角色与权限设计PRD》第三章"双看板设计"、《03_管理端详细PRD》驾驶舱章节（7 模块）、《04_操作端详细PRD》工作台章节（6 模块，布局基线：**待办优先**）。
- 本文档在其上补充 **BI 图表化细节**（图表类型、维度、指标口径、数据来源），数据结构口径见附件《05_数据库设计文档》。

## 二、需求目标

1. 建成三层面板：调解驾驶舱（系统管理员）、调解工作台主管视角、调解工作台调解员视角，覆盖全部核心运营指标。
2. 指标口径全平台唯一（见第 7 章指标口径字典），三层面板与后续 AI 报表共用。
3. 主管/调解员面板严格裁剪，普通调解员不可见任何他人或法院汇总数据。
4. 实施载体：先在多维表格建仪表盘原型验证口径，后迁移网页端正式实施（详见第 13 章待确认）。

## 四、权限规则（页面/按钮/行数据权限）

### 4.1 页面权限

| 面板/模块 | 系统管理员 | 带主管标识的调解员 | 普通调解员 |
|---------|-----------|-----------------|-----------|
| 调解驾驶舱 | ✅ | ❌ | ❌ |
| 调解工作台（主管视角） | ❌ | ✅ | ❌ |
| 调解工作台（调解员视角） | ❌ | ✅（含在主管视角内） | ✅ |
| 法院数据全景 | ❌ | ✅（专属） | ❌ |
| 个人效能页 | ❌ | ✅ | ✅ |
| 多法院切换按钮组 | ❌ | ✅（限绑定法院） | ❌ |

### 4.2 按钮权限

| 按钮/交互 | 归属 |
|---------|------|
| 指标卡片点击下钻 | 各面板使用者，下钻范围受行数据权限约束 |
| 效能排行三维排序切换（结案量/成功率/平均调解时长） | 系统管理员、带主管标识的调解员 |
| 案件类型分布切换（案由分类/纠纷类型一级门类） | 同上 |
| 图表悬停查看数值 | 全部面板使用者 |

### 4.3 行数据权限

| 使用者 | 可见数据范围 |
|-------|-------------|
| 系统管理员 | 全平台所有法院、调解组织、调解员数据 |
| 带主管标识的调解员 | 管辖法院全量案件 + 本人案件；法院切换按钮组仅展示其机构绑定审核通过的法院 |
| 普通调解员 | 仅本人案件、本人费用（实收−退费）、本人效能数据；不出现任何法院/他人汇总 |

> 数据可见性总开关：主管/调解员对某法院的数据可见性以其机构绑定审核通过为前提；绑定停用后对该法院数据（含汇总面板）彻底不可见。

## 五、业务流程

### 5.1 面板数据消费流程

平台各业务操作（分案、调解、结案、费用录入、外呼、文书）→ 数据沉淀 → 按指标口径聚合（驾驶舱每 5 分钟自动刷新，见《03》）→ 三层面板按角色视角渲染 → 使用者发现异常（超期/临期/待审批/待跟进）→ 点击下钻进入对应明细页处理。

### 5.2 主管工作台使用流程

登录 → 调解工作台（主管视角）→ 顶部选择法院（[全部] 或具体法院，切换后所有模块同步刷新）→ 依次处理：今日概览 → 关注事项提醒（我的申请返回/待签署文书/我的待办）→ 预警信息（管辖范围）→ 效能排行（点调解员查收益明细）→ 案件类型分布 → 近期案件动态 → 必要时进入「法院数据全景」做深度分析。

### 5.3 调解员工作台使用流程

登录 → 调解工作台（调解员视角，无法院切换）→ 我的在办/待办/今日结案/成功率 → 个人待办与临期提醒 → 进入个人效能页查看本人趋势与能力矩阵。

### 5.4 边界说明：工作台不含分案环节

分案（含智能分案）属设置层，由系统管理员完成；原"重新指派审核"已并入"申请返回"流程（2026-09-15 统一口径）。调解主管/调解员的个人工作台不出现任何分案类卡片、事项或入口，案件在指派到人后才进入工作台视野；"我的申请返回"为个人退案申请状态展示，不属于分案环节。

## 六、页面模块说明

### 6.1 调解驾驶舱（系统管理员）

目标载体：管理端驾驶舱页面（P0），可先在多维表格建同名仪表盘原型验证口径。

**（1）核心指标卡片（7 项，两行）**：每卡片带环比箭头，点击下钻到对应数据页。

| 指标 | 口径 |
|------|------|
| 总案件数 | 案件全量计数 |
| 调解中 | 调解状态=进行中类目 |
| 已结案 | 结案日期非空 |
| 成功率 | 调解成功数 ÷ 已结案数 |
| 总标的额 | 各案件标的额合计 |
| 本月新增 | 本月新收案数 |
| 派驻调解员 | 在职调解员数 |

**（2）待处理事项 / 全平台预警（双栏卡片组）**：
- 待处理：入驻审核🔴、账号审核🟡、财务审核🟡、申请返回审核🟡（数量角标，点击跳转）；分案审核🔵（智能分案人工确认）
- 预警：超期未结案🔴（结案日期为空且超调解期限）、本月成功率偏低法院🟡、待跟进当事人🟡（外呼多次未接通）、调解超期案件🔵

**（3）各法院数据对比（表格 + 条形图）**：行=法院，列=案件数/调解中/已结案/成功率/标的额/调解员数；成功率低于阈值整行标红；条形图按案件量降序。

**（4）调解员效能排行（Top 10 横向条形榜）**：本月结案量、成功率、平均调解时长（结案日期−委托调解时间）三维排序切换。

**（5）案件趋势图（近 6 个月组合图）**：柱=每月新增案件，折线=每月成功率，悬停显示数值。

**（6）近期重要操作动态（时间线）**：分案执行/审核操作/费用核算/规则配置，显示时间、操作人、内容。

**（7）可选增强（驾驶舱 BI 化）**：纠纷类型分布饼图（一级 11 门类 + 二级 53 类下钻，或按 78 标签挂载）；调解费概览卡（应收/实收/退费合计）；调解组织效能对比（案量、调解员数量）。

### 6.2 调解工作台·主管视角

**顶部：多法院切换按钮组**：[全部] [涪陵区法院] [渝中区法院] [万州区法院]…（数据来源：本人机构绑定法院）。切换后所有模块同步刷新。

**六大模块（布局基线：待办优先）**：
1. **今日概览（3 卡）**：新增案件 / 调解中 / 今日结案 —— 范围=选中法院（无"待分案"卡，分案由系统管理员完成）
2. **关注事项提醒**：我的申请返回（审核中/被驳回，个人）、待签署文书（个人）、我的待办案件 —— 仅个人待办（分案类事项不展示）
3. **预警信息**：超期未结案、调解超期、待跟进当事人、本月成功率偏低 —— 范围=选中法院
4. **调解员效能排行（Top 5）**：选中法院调解员，点击可查看收益明细（调解费下钻）
5. **案件类型分布（本月饼图）**：民间借贷/买卖合同/租赁合同/劳务合同/其他；可切到纠纷类型一级 11 门类（预留 78 标签维度）
6. **近期案件动态（时间线）**：调解完成/文书生成/外呼上传/结案（不含分案/分配类动态）

**主管专属 BI 增强（法院数据全景入口）**：工作台底部/侧边提供「法院数据全景」入口，进入后为全方位可视窗口：
- 案件数据全景：案件量趋势、成功率趋势、类型分布、审理程序分布、标的额区间分布
- 调解员核心数据：效能排行、案件负载（在办案件数）、结案时效
- 调解费查阅：应收/实收/退费/提成（行=调解员，可逐案下钻）
- 全部案件（查阅，含当事人隐私）

### 6.3 调解工作台·调解员视角（个人）

与主管版的差异（严格裁剪）：

| 模块 | 主管 | 调解员 |
|------|------|--------|
| 法院切换按钮组 | ✅ | ❌ |
| 今日概览 | 管辖法院汇总 | **仅本人**：我的在办、我的待办、我的今日结案、我的成功率 |
| 关注事项/预警 | 管辖+个人（含管辖法院申请返回动态） | 仅个人（我的待办、我经手案件的临期/超期、我的申请返回状态） |
| 效能排行 | ✅（他人） | ❌，仅"个人效能"页（本人趋势图） |
| 案件类型分布 | 选中法院本月 | 本人本月案件类型 |
| 近期动态 | 选中法院 | 本人案件动态 |
| 法院数据全景 | ✅ | ❌ |
| 费用 | 管辖查阅+本人录入 | 仅本人费用（实收−退费） |

### 6.4 个人效能页 BI 内容

- 近 6 个月个人结案量柱状图 + 成功率折线
- 案件类型能力矩阵（本人各类型成功率热力）
- 平均调解时长趋势
- 本人费用月度趋势（应收/实收/提成）

## 七、字段字典表格

### 7.1 指标口径字典（关键计算）

| 指标 | 公式 | 备注 |
|------|------|------|
| 成功率 | 调解成功案件 ÷ 已结案案件 | 已结案=结案日期非空 |
| 平均调解时长 | 平均（结案日期 − 委托调解时间） | 剔除异常值 |
| 提成 | 实收调解费 − 退费 | 与《01》费用模型主口径一致 |
| 超期未结案 | 结案日期为空 且 今日−委托调解时间 > 期限规则天数 | 期限规则按法院×案件类型配置 |
| 待跟进当事人 | 外呼记录中 N 次未接通的当事人 | N 可配置（默认 3） |
| 本月新增 | 案件收案时间在本自然月内 | — |

### 7.2 数据来源映射（业务口径）

| 业务数据域 | 关键业务字段 | 支撑的指标 |
|---------|---------|-----------|
| 案件信息 | 案由、纠纷类型、标的额、辖区法院、调解法院、审理程序、收案法官、立案案号、案号、民调案号 | 案件量、类型分布、标的额、法院分布、审理程序分布 |
| 调解工作台 | 调解情况、调解失败原因、结案日期、调解时间、结束日期、委托调解时间、应收调解费、调解服务费、标的额、所属调解组织、指派信息 | 结案量、成功率、失败原因分析、费用类指标、时效类指标 |
| 调解外呼 | 外呼记录字段 | 待跟进当事人预警、外呼活跃度 |
| 文书归档 | 归档文书 | 文书进度指标 |
| 案件当事人 | 原告/被告/第三人信息 | 当事人维度统计 |
| 调解员主数据 | 调解员信息 | 效能排行、派驻调解员数 |
| 调解组织 | 调解员数量、案量、行政区域、调解业务范围 | 组织效能对比 |
| 纠纷类型 | 纠纷门类一级 11 个 / 二级 53 个 / 纠纷类型 | 类型分布的下钻层级 |
| 法院机构 | 法院名称、行政区域、收案量、法官人数 | 法院对比、对标分析 |

> 上表为业务数据域与指标的对应关系；具体数据表与字段结构的技术定义见附件《05_数据库设计文档》。

## 八、增删改查流转规则

**本模块为只读可视化面板，无数据新增/修改/删除操作。**

- 面板所有数据由业务模块（案件管理、外呼、文书、费用等）的操作沉淀后聚合生成；
- 使用者对面板的交互（下钻、切换、排序、悬停）均为查询行为，不产生数据变更；
- 异常处置动作（审批、跟进、纠错）跳转到对应业务模块完成，回写后面板随刷新机制更新（驾驶舱自动刷新周期为每 5 分钟，见《03》）。

## 九、校验&异常场景

| 场景 | 处理规则 |
|-----|---------|
| 数据聚合口径不一致 | 三层面板与 AI 报表共用第 7 章指标口径字典；口径变更须同步修订字典并评审 |
| 主管未绑定任何法院 | 多法院切换按钮组仅显示已绑定且审核通过的法院；无可用法院时按调解员视角渲染 |
| 绑定停用 | 停用后该法院汇总数据（含法院切换项、预警、排行）彻底不可见 |
| 分母为零 | 成功率计算时已结案数为 0 的法院/调解员，该项显示"暂无数据"而非 0% |
| 异常值干扰 | 平均调解时长计算剔除异常值；剔除规则随口径字典维护 |
| 78 标签未到位 | 类型分布先按案由分类/纠纷类型一级门类渲染，标签维度挂载点预留，不阻塞一期 |
| 原型与网页端口径漂移 | 多维表格原型阶段以第 7 章口径字典为验收基准，网页端实施前做口径回归核对 |

## 十一、操作日志规则

本模块为只读可视化面板，不产生业务数据变更，自身不新增操作日志条目。使用者通过面板下钻进入业务模块后发生的操作（审批、纠错、跟进等）按各业务模块的日志规则记录（详见《03_管理端详细PRD》操作日志章节）。指标口径字典的变更须纳入文档评审留痕。

## 十二、非功能需求

1. **刷新时效**：驾驶舱自动刷新周期 5 分钟（继承《03》），重要预警与待处理事项实时推送；主管切换法院后所有模块同步刷新。
2. **权限裁剪刚性**：调解员视角面板在数据层面不得返回任何他人/法院汇总数据（非仅前端隐藏）。
3. **指标口径单一来源**：所有面板共用第 7 章指标口径字典，口径修改需评审后统一生效。
4. **载体兼容**：图表化细节（图表类型、维度、指标）设计为多维表格仪表盘与网页端两种载体共用，避免重复定义。
5. **下钻可达性**：每个异常卡片（超期/待审批/待跟进等）必须可下钻到具体案件或待办列表，不允许"只看数不能办"。
