## 一、需求背景与价值

### 1.1 模块定位

管理端是系统管理员（设置层）的工作平台，核心定位是**全平台监控 + 系统设置 + 元数据管理**。系统管理员通过管理端实现对整个调解平台的运营监控、规则配置、人员管理和数据审计。

### 1.2 设计原则

1. **监控驾驶舱视角**：首页以调解驾驶舱形式呈现全平台核心指标和预警信息
2. **数据驱动决策**：所有管理操作基于真实数据，提供数据对比和趋势分析
3. **配置灵活化**：分案规则、通知渠道、财务规则等均可在后台灵活配置
4. **操作可审计**：所有管理操作记录日志，支持追溯和审计
5. **权限最小化**：系统管理员虽有全量权限，但界面以管理功能为主，不设专门的"我的案件"入口

### 1.3 业务价值

- 将现有飞书多维表工作流升级为统一管理后台，解决各法院数据分散、监控不灵活的问题；
- 智能分案与期限规则配置实现分案均衡与期限合规的自动化管理；
- 费用全口径（应收/实收/退费/提成）透明化，月结快照作为结算对账依据；
- 全量操作审计留痕，满足政务合规要求。

### 1.4 四大功能域归属映射（对齐《00_项目总览PRD》）

智能分案域→智能分案模块；调解执行域→案件管理/人员管理/基础数据/外呼记录/文书管理；费用管理域→调解费报表+系统设置财务配置+人员管理（收益）；调解知识库域→操作日志+系统设置 AI/法规配置（后续阶段）；其余为跨域支撑模块。

## 五、业务流程

### 5.1 智能分案流程

详见《01_角色与权限设计PRD》第五章，包含6个步骤：
1. 选择法院（分案操作前必须先选择法院，规则配置与分案操作均基于法院维度）
2. 待分案案件列表（勾选案件；**自动排除经"申请返回"退回待指案池的案件**——此类案件不受分案规则影响，由管理员在案件管理中人工指派新调解员）
3. 参与调解人员勾选确认（见第5.2节）
4. 智能分案结果展示
5. 人工审核和调整
6. 确认分案

### 5.2 参与调解人员勾选确认

分案执行前的必要环节，仅系统管理员可操作：
1. 勾选范围：所选法院派驻、账号启用状态的调解员（含/不含主管标识）
2. 灵活增减：调解员勾选数量不设上限或固定值，管理员可随时新增或取消勾选
3. 校验规则：带主管标识的调解员至少1人，普通调解员至少1人，否则无法开始智能分案
4. 分案边界：智能分案仅在已勾选的调解员范围内分配案件，未勾选人员不参与

### 5.3 机构绑定审核流程（人员-法院-调解组织）

调解员（含/不含主管标识）在操作端「我的机构绑定」提交的"法院 + 调解组织"绑定申请，统一汇集到人员管理页面由**系统管理员审核**；审核通过后该人员才能看到对应法院的数据。系统管理员也可直接为人员新增/停用绑定（入职配置、离职、调岗）。支持一个人员绑定多个法院、多个调解组织，每条关系独立审核。

流程：人员提交申请 → 系统管理员审核（通过/驳回）→ 通过即生效（人员立即获得该法院数据可见权限）；驳回须填写原因，人员端可见原因并可修改后重新提交。通过/驳回后向申请人发系统内通知（可叠加飞书/短信，通知渠道在系统设置配置）。

### 5.4 退案管理流程（申请返回审核 + 退案池 + 重新指派）【P0·2026-09-17 升级为独立模块】

调解员/主管因无法调解在案件详情发起退案申请（申请返回）→ 驾驶舱"待处理事项"提示待审核数量 → 系统管理员在退案管理模块审核：
- **同意**：案件进入**退案池**（当前调解员清空、标记 `excluded_from_auto_assignment=true`、不回流公共分案池、不参与智能分案平均分配），随后由管理员在本模块人工指派新调解员（直接换人）；
- **驳回**：案件留原调解员名下并回传驳回原因（详见《04_操作端详细PRD》案件详情页）。

**重新指派规则**（2026-09-16 会议确认）：重新指派仅做直接换人处理，不纳入智能分案平均分配逻辑；"重新指派"操作权限与初始分案权限独立拆分，当前阶段仅系统管理员可操作，不下放至调解主管；待重新指派案件量显著提升后再评估下放。全链路（发起/审核/指派）留痕并写入审计日志。

### 5.5 案件关键节点审批流程

结案/司法确认/终结等关键节点需系统管理员或带主管标识的调解员审批，审批动作写入审计日志；系统管理员可强制结案（留痕）、可将案件退回法院（需填写退回理由）。

### 5.6 费用月结流程

次月 1 号自动生成上一个自然月正式报表快照（作为提成结算/对账依据，生成后数值定格）→ 当月数据实时累计、跨月以快照为准 → 补录/纠错后可手动重跑某月报表（覆盖快照，留痕）→ 导出月度结算表。

### 6.5 智能分案

智能分案模块是系统管理员的核心管理功能之一，实现基于三维度权重的智能案件分配。流程见第5.1~5.2节。

**分案规则配置**（每个法院独立配置）：
1. 三维度权重：数量50% / 标的30% / 类型20%（默认值，可调整）
2. 人工审核：是否启用（默认启用）
3. 审核超时时间：默认24小时
4. 分案结果通知渠道：系统内通知/飞书消息/短信（可多选）

> 注意：已取消调解员忙碌值设计，分案时不考虑忙碌阈值。

**分案结果展示**：每个调解员分配的案件数量、总标的额、民商事案件占比、分案规则匹配度说明；支持人工调整（拖拽案件到其他调解员）。

### 6.6 人员管理

提供调解员（含/不含主管标识）的账号管理、权限分配、标签配置、主管标识勾选、机构绑定审核（见第5.3节）等功能。

**权限分配配置项**：
1. 角色分配：系统管理员/调解员（登录身份仅此两种）
2. 主管标识：注册审核时或后续调整勾选（留痕；决定主管专属功能可见性）
3. 管辖范围（带主管标识者）：选择管辖的法院（可多选）
4. 可参与法院（调解员）：选择可参与调解的法院（可多选）
5. 调解组织归属：选择所属调解组织（可多选）
6. 调解员标签：等级/专业领域/收益系数
7. 数据权限：可查看和操作的数据范围

**审核流程**：主管标识的勾选与调整由系统管理员操作（留痕）；调解员收益系数标签变更需系统管理员审核；其他配置变更即时生效。

### 6.7 基础数据管理

统一管理平台的基础元数据：法院信息、调解组织、案由分类、入驻法院项目审核。

> **绑定主数据约束**：法院与调解组织是操作端"机构绑定"下拉选项的**唯一数据来源**——人员绑定时只能选择本模块维护、且状态为"启用/合作中"的法院与调解组织，不能自行填写名称。因此新增一家合作法院/调解组织，必须先在本模块录入，人员才能绑定。

**操作功能**：
- 法院：新增、编辑、删除（需二次确认，有关联数据时禁止删除）、查看详情（含案件统计、调解员列表）、配置法院分案规则（跳转到智能分案模块）
- 调解组织：同上口径维护
- 入驻法院项目审核：审核带主管标识的调解员提交的入驻申请——查看项目详情（15个字段）、审核通过（法院正式入驻，可配置分案规则，可接收案件）、审核拒绝（需填写拒绝理由，通知提交人）

字段设计见第7章字段字典。

### 6.8 调解费报表（全平台）

**模块定位与费用口径**：系统管理员在本模块查看**全平台**调解费，掌握应收/实收/退费/提成，对费用进行纠错与月结；操作端带主管标识的调解员只看管辖范围（见《04_操作端详细PRD》第十四章），口径完全一致。

**统一口径**：应收调解费（**2026-09-16 校准**：按「诉讼费（全国统一标的额分段标准）× 法院比例（40%–50% 逐法院预置）」计算）、实收调解费（人员录入，可打折/优惠）、退费（人员录入）、**调解员提成 = 基于实收调解费总和按档位规则核算**（核算原值为实收调解费总和，档位细则待业务补充，见第13章；过渡期报表快照沿用「实收−退费」）。

**费用总览**：
- 全平台汇总卡：选定范围的**应收、实收、退费、提成、优惠折让（应收−实收）**及环比。
- 对比：各法院、各调解组织费用对比柱状图；近 6/12 个月应收 vs 实收 vs 提成趋势；按案件分类（民事/商事）构成。

**调解员费用数据表（可下钻，核心）**：以调解员为行（调解员、所属法院/调解组织、计费案件数、标的合计、应收、实收、退费、提成），支持排序、导出。点击行展开逐案明细（案号、案由、标的额、应收、实收、退费、提成、费用状态）；再点案件进详情看每笔费用流水（方式、时间、凭证、折让说明、录入人）。一人多法院时按法院拆分行并给小计/合计。

**案件费用明细与纠错**：全平台逐案费用列表；管理员可对误录的实收/退费做冲销或补录（必须填写原因并写操作日志）；风险标记规则见第9.5节。

**月度报表生成与月结**：见第5.6节。收费规则（决定应收）在"系统设置→财务配置→调解费收费规则"维护（见第6.9节）。

### 6.9 系统设置

提供平台全局参数的配置功能，仅系统管理员可操作。

**分案规则设置**：全局分案规则（三维度权重默认值、人工审核默认是否启用、审核超时默认时间、默认通知渠道）+ 法院分案规则（各法院独立配置列表，点击进入具体法院的规则配置）。

**通知配置**：通知渠道配置（系统内通知开关、飞书消息、短信）；通知模板管理（分案结果/案件状态变更/待办事项提醒/系统公告四类模板）。渠道参数配置的技术细节见附件《06_API接口设计文档》。

**AI模型配置（后续阶段，占位）**：第一阶段不实施，菜单隐藏或置灰。含 AI 服务商选择（DeepSeek/豆包等）、模型参数、案件分析/类案检索/调解策略提示词模板等配置项。**【2026-09-17 补充：网页端AI智能体安全与合规配置】**：①大模型 API 密钥仅存后端（环境变量/密钥管理服务），前端与数据库普通配置不存任何密钥；②数据脱敏开关：传给大模型时可配置隐藏身份证号、手机号等敏感字段，默认开启；③限流配置：按人/按组织的 AI 调用频率上限，防止高频调用消耗大量额度；④AI 调用日志：每次调用记录操作人、案件 ID、输入、输出，可追溯（写入操作日志体系）。详见《00》第十六章。

**法规库配置（后续阶段，占位）**：第一阶段不实施，菜单隐藏或置灰。含法规库服务商选择、数据更新频率、法规分类管理。

**各法院规则设定（2026-09-16 会议新增版块，决定费用核算口径）**：按**法院维度**独立配置三类规则，未配置法院不可参与费用核算（保存时校验）。所有规则形成书面配置文档，确保系统自动核算无模糊地带：

- **① 调解费规则（已确认口径）**：
  - 计算链路：`案件标的额 →〔全国诉讼费分段累计标准（系统内置）〕→ 诉讼费 ×〔该法院预置比例（40%–50%）〕→ 应收调解费`；
  - 诉讼费按全国统一标的额分段标准（《诉讼费用交纳办法》）计算，与案由、民事/商业属性无关，无需额外适配；全国统一诉讼费核算标准表待线下对接同步后内置落库（含全量公式校验）；
  - 法院比例逐法院配置，预置于应收字段，支持生效日期与调整留痕；
  - 保留【试算器】：输入标的额即时显示诉讼费、应收调解费与命中比例。
- **② 调解员提成规则（框架已定，数值待业务补充）**：
  - 核算原值固定为**实收调解费总和**；标的额仅用于业务风险判断，不参与提成计算；
  - 档位/阶梯规则表结构：档位区间（下限/上限）→ 提成比例或固定额（具体数值待业务补充，见第13章待确认清单）；
  - 单笔费用跨档位导致的提成差额属正常绩效差异，不做特殊规则调整（财务已重新校验确认无逻辑错误）；
  - 退费规则：严谨性校验结果与优化方案同步至系统配置，退费影响提成发放（退费下月扣除等细则随档位数值一并补充），避免调解员自主调整费用影响发放；
  - 需对现有提成核算 Excel 表公式逻辑、原值套用规则做全量校验，排查原规则不严谨导致的核算偏差。
- **③ 调解主管激励规则（框架已定，数值待业务补充）**：
  - 与调解员提成规则同构：基于实收调解费总和的档位规则，面向带主管标识的调解员；
  - 具体档位/比例数值由业务方后续补充，配置表结构与②一致（见第13章待确认清单）。

**其他财务配置**：
- **实收/退费录入与预警**：优惠折让预警阈值（实收/应收低于某比例时报表标黄，仅提示不阻断）；退费上限（默认退费累计不得超过实收累计）；月结时间（每月 1 号自动生成上月报表，可改时点、可手动重跑）。
- **调解员等级系数（扩展预留）**：等级系数（默认档位见第7.9节）字段保留；是否在提成基础上再乘等级系数**待业务确认**，确认后在此开关启用。
- **提成核算细化口径**：见第13章待确认清单。

**安全设置**：密码策略（最小长度/复杂度要求/有效期）、登录策略（失败锁定次数/锁定时长/IP白名单）、会话超时时间、操作日志保留时长、数据备份策略。

### 6.10 调解期限规则配置【P0】

按**法院 × 案件类型**配置调解期限与可延长规则。期限一律由规则引擎计算，前端只读渲染（"诉前30日"仅为默认值）；影响我的案件列表、调解进度看板、驾驶舱/法院数据全景三处"剩余天数/临期高亮"的渲染。

**页面骨架**：规则列表表格（法院、案件类型、期限天数、是否可延长、延长上限、临期阈值、生效状态、操作）+ 新建/编辑表单（字段同上，法院与案件类型联合唯一校验）。字段定义见第7.7节。

**交互与约束**：新增/编辑规则需通过生效校验（同法院×类型不得重复启用规则）；规则变更后重算受影响案件的剩余天数，前端列表随之变化。

### 6.11 AI报表（日/周/月报，后续阶段·占位待细化）

> **模块状态**：占位章节，后续优化阶段（第一阶段不实施），属「调解知识库」功能域；细节待业务确认后细化，本节仅锁定数据来源与栏目骨架。

AI 基于平台数据自动生成调解运营**日报/周报/月报**，替代现有手工填报（涪陵法院运营部日/周/月报），系统管理员查看全平台报表，可导出、可下发。

**数据来源**（不新增统计口径，复用现有聚合）：案件量/成功率/状态分布（含收案/退案/在调、成功四分类、委派量）；费用口径（收费/退费/实收/提成）；人员构成（审核通过的机构绑定关系）。

**报表栏目骨架**（对标现有运营日/周/月报格式）：
- **数据区**：收案数/退案数/在调案数；调解成功数（拆四类：程序性撤诉/履行性撤诉/调解书/司法确认）；收费金额/补贴金额/退费金额/实际收费；调解成功率；整体 vs 个案 vs 系列案（物业金融/其他）三条线；多周期口径（今日/本周/本月/累计）
- **分析区**：结案分析（数量/占比/平均调解时长）、案由及成功率、失败原因五分类（联系不到当事人/分歧较大/明确拒绝/其他/撤回）
- **人员区**：运营部人员构成（调解员/主管/辅助等）
- **文字区**：工作进展及计划、需院方或总部支持事项、平台问题（AI 生成草稿+人工确认）
- **生成节奏**：每日下班前/每周五/每月底（对齐现有填报时间点），支持手动生成与重生成

### 6.14 退案管理（退案池与重新指派）【P0·2026-09-17 新增】

集中管理因调解员/主管无法调解而退回的案件，是重新指派的统一入口（流程见第5.4节，接口见《06》5.3.7/5.3.8/5.4.3，数据表见《05》case_return_requests）。

**页面结构**：两个标签页——「待审核申请」与「退案池」。

**标签页1：待审核申请**（申请返回审核列表）：
- 筛选区（法院、申请人、申请日期范围、搜索案号/当事人）；
- 统计卡片（待审核数、本周新增、本月同意/驳回）；
- 列表：案号、法院、案件类型、标的额、原调解员、申请人（调解员/主管）、申请时间、申请理由、审核状态、操作（同意/驳回）；
- 驳回必须填写原因，回传申请人；同一时刻同一案件仅一条待审核申请（重复发起返回 409 `CASE_RETURN_PENDING`）。

**标签页2：退案池**（审核同意后的待重指派案件）：
- 列表：案号、法院、案件类型、标的额、原调解员、退回日期、退回原因、滞留天数（高亮超期未指派）、操作（指派新调解员/批量指派）；
- **人工指派**：弹出人员选择器（限该法院派驻、启用状态的调解员，含/不含主管标识），直接换人，不受智能分案三维度权重影响，不回流公共分案池；支持多选案件批量指派；
- 指派完成向新旧调解员分别发通知（渠道随系统设置），并写入分案记录（方式=人工指派）与审计日志。

**与其他模块的关系**：驾驶舱"待处理事项"展示待审核数量；智能分案待分案列表**自动排除**退案池案件；案件管理「分案与审计」标签页可查看完整退案轨迹（申请/审核/重新指派全链路）。

### 6.15 操作日志

提供全平台所有用户操作的审计日志查询功能。详见第11章。

### 6.16 数据同步（Browser 智能体案件抓取）【P0·2026-09-19 新增】

**产品形态（架构决策）**：Browser 智能体不内嵌于网页（浏览器安全模型禁止网页跨域驱动第三方站点与模拟其登录），也非用户专属客户端，而是**部署在云服务器上的独立抓取服务**（Playwright 无头浏览器 + 抓取脚本，带人工登录接管）。本页面是智能体在产品内的唯一入口与监控面板；数据落库为**飞书多维表（项目唯一数据源）**，后续所有端读数据均走多维表。

**已确认的关键决策**：
- 触发方式：仅人工手动触发（架构预留定时调度位，本期不开放）；
- 登录态：管理员本人登录人民调解平台（扫码/验证码在任务面板人工接管），登录会话仅存活于单次任务的无头浏览器实例，任务结束销毁，凭据零落库；
- 触发角色：仅系统管理员；
- 运行环境：自有云服务器（智能体服务与网页后端同机房部署）。

**页面结构**：三个区域——「新建同步任务」「进行中任务面板」「历史任务列表」。

**区域1：新建同步任务**：
- 表单：数据来源（默认人民调解平台，预留扩展）、抓取范围（时间范围/案号区间/指定案号）、预计条数提示（单轮上限 500 条，超限提示分批）；
- 「开始同步」按钮（二次确认弹窗：提示需人工完成登录接管）。

**区域2：进行中任务面板**（任务全生命周期可视化）：
- 状态机：`排队中 → 等待登录（人工接管）→ 抓取中 → 写入多维表中 → 已完成 / 失败（可重试）`；
- 等待登录态：内嵌显示人民调解平台登录页截图/二维码，管理员用本人账号扫码或输入验证码完成接管（接管超时 10 分钟自动取消任务）；
- 抓取中：实时进度（已抓取/预计、当前页、失败重试次数）；
- 写入中：多维表写入进度（批量写入，遇限流自动排队重试）；
- 异常处理：页面改版/风控拦截/验证码二次触发时任务暂停并推送告警，管理员处理后可「继续」或「终止」。

**区域3：历史任务列表**：
- 列表：任务号、发起人、抓取范围、抓取条数、新增/更新（去重后）、写入结果、耗时、状态、操作（查看日志/重试/下载报告）；
- 任务日志：智能体每步操作留痕（打开页面/登录/翻页/解析/写入），与操作日志模块（第十一章）联动，可审计到「谁在哪台服务器上跑了什么任务」。

**去重与幂等**：以案号为唯一键，多维表已存在的案件只更新变更字段（留更新痕迹），不存在的新增；重复执行同一范围任务不产生脏数据。

**与其他模块的关系**：新入库案件进入「智能分案」待分案池；驾驶舱监控智能体服务运行状态；数据同步结果计入操作日志；后续若开放定时同步，仅在后端加调度器，本页面无需重构。

**风险与对策**：
1. 反爬/页面改版 → 抓取脚本按选择器模块化，改版只需更新脚本，不动产品；
2. 登录风控（异地登录提醒）→ 服务器固定 IP + 固定 UA 指纹；
3. 多维表 OpenAPI 限流 → 批量写入 + 失败重试队列；
4. 责任边界 → 产品定位为辅助同步工具，抓取行为全程留痕可审计。

## 九、校验&异常场景

### 9.1 智能分案校验

| 场景 | 校验规则 |
|-----|---------|
| 人员勾选 | 带主管标识的调解员至少1人、普通调解员至少1人，否则无法开始智能分案 |
| 勾选范围 | 仅所选法院派驻、账号启用状态的调解员可选 |
| 待分案范围 | 经"申请返回"退回待指案池的案件自动排除，不受分案规则影响 |
| 法院选择 | 分案操作前必须先选择法院 |

### 9.2 机构绑定防重与约束

| 场景 | 校验规则 |
|-----|---------|
| 重复绑定 | 同一"人员 + 法院 + 调解组织"只允许存在一条有效（待审核/已通过）绑定，重复申请给出提示 |
| 多绑定并存 | 不同法院/组织可同时存在多条申请与绑定（类似项目经理兼管多个项目） |
| 重新申请 | 被驳回的绑定允许修改后重新申请（保留历史）；已解绑的法院允许重新申请 |
| 主驻唯一 | 一个人员仅允许 1 个"主驻"法院，新增主驻时自动取消原主驻标记 |
| 主数据停用 | 法院/调解组织若被管理员停用，其下已有绑定同步变为不可用并提示 |
| 申请来源 | 申请法院/组织只能从主数据下拉选择，不可自由填写 |

### 9.3 基础数据删除约束

| 场景 | 校验规则 |
|-----|---------|
| 删除法院/组织 | 有关联数据时禁止删除 |
| 批量删除案件 | 需二次确认 |

### 9.4 期限规则校验

| 场景 | 校验规则 |
|-----|---------|
| 联合唯一 | 同法院×案件类型不得重复启用规则 |
| 延长上限 | "是否可延长"开启时，延长上限必填 |

### 9.5 费用风险标记

| 场景 | 处理规则 |
|-----|---------|
| 退费超限 | 退费累计>实收，自动标红 |
| 折让过大 | 实收显著低于应收（折让超预警阈值），标黄 |
| 长期未录 | 已结案但长期未录实收，标红/标黄 |
| 退费上限 | 默认退费累计不得超过实收累计 |
| 纠错权限 | 仅系统管理员可冲销/补录，且必填原因 |

### 9.6 审核类异常

| 场景 | 处理规则 |
|-----|---------|
| 驳回绑定申请 | 驳回原因必填 |
| 拒绝入驻项目 | 拒绝理由必填，通知提交人 |
| 退回案件给法院 | 退回理由必填 |
| 审核超时 | 智能分案人工审核超时（默认24小时），按法院分案规则处理 |

| 法院 | 下拉选择 | 按法院筛选，支持多选 |
| 案件状态 | 下拉选择 | 待分案/待受理/调解中/待签署/已结案/已结束/已退回 |
| 案件类型 | 下拉选择 | 民间借贷/买卖合同/租赁合同/劳务合同/其他 |
| 调解员 | 下拉选择 | 按调解员筛选 |
| 日期范围 | 日期选择 | 按立案日期/结案日期筛选 |
| 关键词搜索 | 文本输入 | 案号/当事人姓名/手机号模糊搜索 |

### 10.2 费用报表筛选

月份（默认当月）、法院、调解组织、调解员、案件分类；调解员费用数据表支持排序、导出。

### 10.3 外呼记录筛选

时间范围、法院、调解员、外呼结果（已接通/未接通/关机/空号/其他）。

### 10.4 文书管理筛选

时间范围、法院、调解员、文书类型（调解协议书/调解笔录/收费告知书/延期申请书/其他）、签署状态（未签署/已签署/已作废）。

### 10.5 操作日志筛选

时间范围、操作人、角色、操作模块（案件管理/智能分案/人员管理/系统设置/调解费报表等）、操作类型（新增/编辑/删除/审核/登录/导出等）、操作结果（成功/失败）。

### 10.6 排序与排行规则

- 调解员效能排行：Top 10（驾驶舱、数据概览平台总览显示）
- 分案结果展示：按调解员维度汇总案件数量/标的额/民商事占比排序展示
- 各法院数据对比表格：按选定指标排序

## 十一、操作日志规则

### 11.1 日志记录范围

全平台所有用户操作均记录审计日志，包括：操作时间、操作人、角色、操作模块、操作类型（新增/编辑/删除/审核/登录/导出等）、操作内容、IP地址、操作结果（成功/失败）。

### 11.2 强制留痕的操作

| 操作 | 留痕要求 |
|-----|---------|
| 主管标识勾选与调整 | 记录操作人、时间、变更前后状态 |
| 机构绑定审核（通过/驳回/直接新增/停用解绑） | 记录审核人、审核时间、审核结论、原因 |
| 案件关键节点审批（结案/司法确认/终结） | 审批动作写入审计日志 |
| 强制结案 | 写入审计日志 |
| 案件删除、退回法院 | 留痕，退回理由入日志 |
| 费用纠错（冲销/补录） | 必填原因并写操作日志 |
| 月度报表手动重跑 | 留痕 |
| 收益系数标签变更 | 审核留痕 |

### 11.3 日志查询与统计

- 查看日志详情
- 导出日志（Excel）
- 按操作人统计操作次数
- 按模块统计操作分布
- 日志保留时长在安全设置中配置

## 十二、非功能需求

### 12.1 数据刷新机制（驾驶舱）

- 自动刷新：每5分钟自动刷新
- 手动刷新：页面顶部"刷新"按钮
- 实时推送：重要预警和待处理事项通过系统通知实时推送
- 最后更新时间：页面顶部显示

### 12.2 通知能力

系统内通知、飞书消息、短信三渠道，渠道与模板在系统设置统一配置；分案结果、绑定审核结果、案件状态变更、待办提醒等按配置触达。

### 12.3 财务时点要求

- 每月 1 号自动生成上月正式报表快照（可改时点、可手动重跑）
- 当月实时累计、跨月以快照为准，界面明确标注口径
- 提成核算与审核节奏（细化口径待确认，见第13章）：法院主管每月5日提案件明细→财务8日提银行到账→初审8日/复审10日/终审12日

### 12.4 安全要求

密码策略（最小长度/复杂度/有效期）、登录失败锁定、IP白名单、会话超时、操作日志保留时长、数据备份策略均在安全设置中配置。

### 12.5 性能与可用性要求

- 驾驶舱自动刷新周期 5 分钟，重要预警实时推送
- 列表类页面支持分页、筛选、导出
- 一人多法院数据按法院拆分行并给小计/合计，避免聚合歧义

### 12.6 占位模块约束

AI报表、AI模型配置、法规库配置为后续阶段占位，第一阶段菜单隐藏或置灰，不提供部分功能。
