## 一、需求背景与价值

### 1.1 背景

问问调解平台正在从飞书多维表工作流升级为独立的网页管理后台。经过多轮讨论，明确了平台的核心架构思路：

**两层架构设计**：

1. **设置层（系统管理员）**：负责全平台的数据监控、系统设置、元数据管理，是平台的"管理者"视角。系统管理员拥有全量权限（设置层独有权限 + 操作层所有权限），但定位上不涉及日常调解操作，不设专门的"我的案件"入口。
2. **操作层（调解员，可带主管标识）**：负责具体法院、具体案件的调解操作，是平台的"执行者"视角。带主管标识的调解员额外拥有管辖查阅与结案审批权限。

现有多维表"调解工作台"包含84个字段，涵盖案件基本信息、法院信息、当事人信息、调解组织与人员、时间信息、调解结果、文书管理、电子签章、外呼记录、费用信息、会议信息等完整业务流程（迁移取舍见第13章待确认）。

### 1.2 与四大功能域的对应关系

| 功能域   | 本 PRD 承担内容                         | 详细设计所在文档     |
| ----- | ---------------------------------- | ------------ |
| 智能分案  | 分案权限归属（仅系统管理员）、分案规则配置权限            | 《03》智能分案章节   |
| 调解执行  | 案件操作权限边界（主管查阅/调解员操作）、机构绑定与数据可见性总开关 | 《04》各章节      |
| 费用管理  | 第七章费用模型与三费权限矩阵、调解员管理（标签/效能/收益）权限   | 《03》《04》费用章节 |
| 调解知识库 | AI/法规库模块的操作层权限边界                   | 《04》后续阶段章节   |

> 角色体系（两级角色 + 主管标识）与机构绑定是四大域之上的横切约束；驾驶舱/工作台/系统设置为跨域支撑。

### 1.3 价值

- 两层架构分离使"管理监控"与"案件执行"职责清晰，权限模型仅两值角色+一个布尔标识，实施与审计成本低；
- 机构绑定作为数据可见性总开关，一人多法院/多组织灵活扩展；
- 财务可追溯：标签体系与费用三要素（应收/实收/退费）挂钩，月度报表自动月结。

## 二、需求目标

1. **两层架构明确划分**：系统管理员（设置层，全平台监控+设置+元数据+智能分案+财务审核，无"我的案件"入口）；调解员（操作层，含/不含主管标识，具体案件操作）。
2. **系统管理员定位优化**：登录后默认进入调解驾驶舱；拥有全量权限，可通过"全部案件"查看和操作任何案件。
3. **调解员（主管标识）定位优化**：注册时统一为调解员，主管标识由管理员注册审核时勾选；登录后默认进入调解工作台；以管辖法院数据查阅为主；拥有调解员全部操作权限；可查看当事人隐私信息和调解员个人收益明细；多法院按钮切换。
4. **信息看板重构**：系统管理员看全平台监控驾驶舱；带主管标识调解员看管辖法院工作台（详见《03》《04》《07》）。
5. **其他目标**：数据看板多维度切换、智能分案法院选择流程（仅管理员）、调解员标签体系、系统设置元数据管理、入驻法院项目管理。

### 2.1 核心设计原则

- **两层架构分离**：设置层与操作层明确分离；
- **全量权限与定位分离**：系统管理员能力上全量，定位上是设置层，不设日常调解操作入口；
- **权限最小化**：每个角色只能访问和操作其职责范围内的数据和功能；
- **数据隔离**：带主管标识调解员只看管辖法院范围数据，普通调解员只看自己的案件；
- **灵活配置**：主管标识为全局属性，支持管辖多个法院、一人多调解组织；
- **财务可追溯**：标签与案件收益挂钩，支持月度调解费报表生成；
- **查阅与操作分离**：主管标识调解员管辖数据经「法院数据全景」查阅，但不具备分案、名册管理、财务审核等管理操作权限；
- **信息看板差异化**：管理员偏"监控驾驶舱"，主管标识调解员偏"工作台"。

### 3.3 角色详细定义

#### 3.3.1 系统管理员（设置层）

**角色定位**：平台最高权限管理者。核心职责是全平台数据监控、系统设置、元数据管理。能力上拥有全量权限（设置层独有权限 + 调解员所有操作层权限），可通过"全部案件"查看和操作任何案件内容；但定位上是设置层，**不设专门的"我的案件"菜单入口**。登录后默认进入调解驾驶舱。

**核心权限**：

| 权限分类      | 权限模块                 | 具体权限                                       |
| --------- | -------------------- | ------------------------------------------ |
| **全平台监控** | 信息看板                 | 查看调解驾驶舱（核心指标、待处理事项、各法院对比、预警信息）             |
|           | 数据概览                 | 查看全平台所有法院的汇总数据和各法院单独数据                     |
|           | 案件监控                 | 查看、编辑、删除所有法院的所有案件                          |
|           | 外呼/文书监控              | 查看全平台所有外呼记录、文书                             |
| **系统设置**  | 分案规则                 | 配置全平台和各法院的分案规则                             |
|           | 通知配置                 | 配置通知渠道和通知模板                                |
|           | AI模型配置               | 配置AI模型参数和API                               |
|           | 法规库配置                | 配置法规库数据源                                   |
|           | 财务配置                 | 配置调解费收费规则（决定应收）、折让预警阈值、月结时点；等级系数为扩展预留      |
|           | 安全设置                 | 配置系统安全策略                                   |
| **元数据管理** | 法院信息                 | 新增、编辑、删除法院信息                               |
|           | 调解组织                 | 新增、编辑、删除调解组织，配置关联法院                        |
|           | 案由分类                 | 管理案件案由分类                                   |
|           | 人员管理                 | 管理系统管理员、调解员账号（含注册审核时勾选主管标识）                |
|           | 权限分配                 | 分配人员角色、管辖范围、调解组织关系                         |
| **核心操作**  | 智能分案                 | 执行所有法院的智能分案、人工指派、审核分案结果                    |
|           | 费用管理                 | 查看全平台调解费报表、费用冲销/补录纠错（留痕）、次月1号月结与手动重跑、导出结算表 |
|           | 入驻审核                 | 审核带主管标识调解员提交的入驻法院项目                        |
|           | 标签配置                 | 配置调解员等级、专业领域、收益系数标签                        |
| **审计**    | 操作日志                 | 查看全平台所有用户的操作日志                             |
| **操作层权限** | 案件/外呼/文书操作           | 可通过"全部案件"进入任何案件详情执行调解操作                    |
|           | 法规知识库/AI智能体（后续阶段，占位） | 查询引用法规、使用AI功能                              |

**数据范围**：全平台所有法院、所有调解组织、所有人员、所有案件数据。

#### 3.3.2 调解员·主管标识（操作层）

**角色定位**：**带主管权限的调解员**。主管不是独立角色，而是调解员的属性，由系统管理员在注册审核时勾选。带标识者拥有调解员全部功能（我的案件/待办/外呼/文书/个人效能/调解进度看板/调解排期日历），并额外拥有★「法院数据全景」（管辖法院全量数据查阅）+「审批结案」（结案/司法确认/终结等关键节点审批）+「全组收益明细」查阅。**不做分案、不管名册**。属于"操作层"，共用操作端布局。

**登录后默认页面**：调解工作台（工作台视角）。

**核心权限**：

| 权限分类               | 权限模块                 | 具体权限                               | 权限类型 |
| ------------------ | -------------------- | ---------------------------------- | ---- |
| **工作台**            | 信息看板                 | 查看调解工作台，多法院按钮切换                    | 查阅   |
| **专属数据窗口**         | ★法院数据全景              | 管辖法院案件数据+调解员核心数据全方位可视化（普通调解员无）     | 查阅   |
| **专属操作**           | 审批结案                 | 结案/司法确认/终结等关键节点审批（写入审计日志）          | 操作   |
| **调解操作**           | 我的案件                 | 直接参与案件调解，拥有调解员的所有操作权限              | 操作   |
|                    | 调解进度看板               | 拖拽推进个人案件阶段，遇审批节点提交审批+留痕            | 操作   |
|                    | 调解排期日历               | 新建/改期/查冲突（本人排期）                    | 操作   |
|                    | 外呼记录                 | 管理个人外呼记录，上传录音                      | 操作   |
|                    | 文书管理                 | 生成、预览、签署、下载个人调解文书（按法院模板）           | 操作   |
|                    | 费用录入                 | 对**本人负责案件**登记实收调解费、退费（逐笔留痕，提成自动算）  | 操作   |
|                    | 个人效能                 | 查看个人调解效能数据                         | 操作   |
|                    | 法规知识库/AI智能体（后续阶段，占位） | 查询引用法规、使用AI功能                      | 操作   |
| **项目申请**           | 入驻法院项目               | 新建、添加、查看自己提交的入驻法院项目                | 操作   |
| **数据查阅（并入法院数据全景）** | 案件/调解员/调解费/外呼/文书查阅   | 管辖法院全量数据（含当事人隐私、调解员收益明细）作为全景页子视图呈现 | 查阅   |

**明确不具备的权限**：智能分案、分案规则配置、费用纠错/月结、收费规则配置、调解员标签配置、人员权限分配、基础数据管理、系统设置、案件删除、操作日志、入驻法院审核（明细见第4章权限矩阵）。

**数据范围**：查阅范围=管辖法院范围内的所有案件（含当事人隐私）、人员、财务数据（含调解员个人收益明细）；操作范围=个人参与的案件（与调解员相同）。

**特殊说明**：

- 本质是带主管权限的调解员：操作端所有页面（含调解进度看板、调解排期日历）均可见可用；
- 与普通调解员的差异仅三项：★法院数据全景 + 审批结案 + 全组收益明细查阅；
- **不做分案、不管名册**；
- 可管辖多个法院，信息看板支持多法院按钮切换；
- 账号需系统管理员审核通过后生效（审核时勾选主管标识）；
- 可新建入驻法院项目，提交后由系统管理员审核。

#### 3.3.3 调解员（操作层）

**角色定位**：负责具体案件的调解工作。登录后默认进入个人工作台。

**核心权限**：工作台（个人待办、案件统计、效能数据）、我的案件（查看和操作分配给自己的案件，申请返回）、调解进度看板、调解排期日历、外呼记录、文书管理（生成/预览/签署/下载/个人模板管理）、个人效能、法规知识库（后续阶段占位）、AI智能体（后续阶段占位）。

**数据范围**：仅分配给自己的案件和个人相关数据。

**特殊说明**：

- 不能直接退回案件，可以**申请返回**（必填理由，由系统管理员审核；可多次发起，每次留痕）。管理员同意后案件进入管理端**退案管理**模块的退案池（清空当前调解员、不再纳入智能分案规则体系），由系统管理员在该模块人工指派新调解员；驳回则案件留在原调解员名下继续调解并回传驳回原因；
- 可属于多个调解组织，参与多个法院的调解工作；
- 标签由系统管理员配置，影响财务收益核算；
- **已取消忙碌值设计**：不再根据当前案件数量判断调解员忙碌状态。

### 4.3 行数据权限

| 角色       | 数据范围                                               |
| -------- | -------------------------------------------------- |
| 系统管理员    | 全平台全量数据（不受绑定限制）                                    |
| 调解员·主管标识 | 查阅=**本人已绑定且审核通过**的法院（可多法院）全量数据（含隐私、收益明细）；操作=个人参与案件 |
| 调解员      | 仅个人数据，且其案件所属法院必须是本人已绑定且审核通过的                       |

**机构绑定：操作层数据可见性的总开关（重要）**：

调解员（含/不含主管标识）**不是账号一开通就能看到法院数据**，而必须先完成"法院 + 调解组织"绑定并通过审核：

1. **主数据由系统管理员维护**：法院、调解组织名称只能由系统管理员在后台录入维护，人员绑定时只能从下拉列表选择，不能自建名称；
2. **人员主动申请绑定**：在「我的机构绑定」选择法院+调解组织提交申请；**支持一个账号绑定多个法院、多个调解组织**；
3. **系统管理员审核生效**：申请状态 待审核→通过/驳回；**只有审核通过的绑定法院，其案件与看板数据才对该人员可见**；
4. **审核前不可见**：无任何已通过绑定时，登录进入受限引导页，业务列表/看板为空态，只能去申请或查看审核状态；
5. **接口层强约束**：所有操作层数据查询统一注入"本人已绑定且审核通过的法院集合"作为过滤条件，前端隐藏菜单不能替代后端过滤；
6. **管理员亦可直接指派**：除人员主动申请外，系统管理员也可在后台直接为人员新增/停用绑定（用于入职统一配置、离职、调岗），两种途径走同一张绑定关系表、同样留痕；
7. **解绑/变更（彻底不可见）**：一旦解绑某法院，该账号对该法院**案件信息彻底不可见**（含历史案件，不是只读保留），后端查询立即剔除；重新绑定审核通过后才恢复可见。变更按"新增绑定+解绑旧绑定"保留操作轨迹；支持同时持有/提交多条绑定，驳回后可重新申请；
8. **业务三级关系**：法院（主体）→委派给调解组织（一家法院可多家组织）→组织分配给调解员；带主管标识的调解员同时兼具管辖职责（既管团队也亲自办案）。

> 详细交互见《04》「我的机构绑定」章节；管理端审核见《03》；表结构与接口见附件《05》《06》。

## 五、业务流程

### 5.1 权限分配流程（注册→审核→开通）

```
用户注册（手机号验证码）
    ▼
统一注册为调解员（无需选择是否主管）
    ▼
填写基本信息（姓名、手机号、所属法院、所属调解组织）
    ▼
提交注册申请：
    ① 账号状态置为待审核
    ② 系统自动将注册时选择的法院+调解组织生成一条机构绑定申请（待审核）
    ▼
系统管理员审核（账号审核与绑定审核同队列展示；审核时勾选「是否为主管」）
    ├─ 审核通过 → 账号激活（含勾选结果）+ 绑定通过 → 数据可见性即时开通
    └─ 审核拒绝 → 通知用户 → 可重新申请（重新提交时更新绑定申请）
```

**注册与机构绑定的衔接规则**：

- 注册时选择的"所属法院+所属调解组织"不是直接赋权，而是自动生成机构绑定申请，与管理员代指派、登录后自助申请的绑定走同一张绑定关系表、同一审核流，保证数据可见性只有"绑定通过"一个开关；
- 账号审核通过但绑定被驳回/未通过时，账号可登录但看不到任何法院数据（已通过绑定法院集合为空，返回无有效绑定提示）；
- 登录后仍可在"我的机构绑定"继续申请其他法院/组织。

### 5.2 法院归属和调解组织关系配置流程

**配置主体**：系统管理员（唯一可配置者）。配置内容：管辖范围分配（为带主管标识调解员分配管辖法院，可多选）、调解组织归属（为组织配置关联法院，可多选）、人员归属（为调解员配置所属组织和可参与法院）、主管标识（注册审核时勾选，或后续在人员管理中调整，调整留痕，即时生效）。配置入口：系统设置→人员管理→权限分配。

```
带主管标识的调解员新建入驻法院项目
    ▼
填写法院基本信息
    ▼

    ▼
系统管理员审核
    ├─ 审核通过 → 法院正式入驻 → 可配置分案规则 → 可接收案件
    └─ 审核拒绝 → 通知提交人 → 可修改后重新提交
```

| 法院地址        | 文本    | ✅   | 详细地址           |

### 5.4 智能分案法院选择流程（仅系统管理员）

```
步骤1：选择法院（仅系统管理员可见此页面，含法院分案规则概览）
    ▼ 选择法院后
步骤2：待分案案件列表（勾选/全选）
    ▼
步骤3：参与调解人员勾选确认
    ▼
步骤4：智能分案结果展示 → 步骤5：人工审核和调整 → 步骤6：确认分案
```

**参与调解人员勾选规则**：

1. **人员范围**：仅展示所选法院派驻、账号状态为启用状态的调解员（含/不含主管标识）；
2. **勾选确认**：管理员通过复选框勾选参与本次分案的调解员（主管标识者带标识展示），作为候选人员池；未勾选者不参与本次分案；
3. **灵活增减**：可随时新增/取消勾选，人数不设上限或固定值，由管理员按本次案件量灵活确定；
4. **校验规则**：带主管标识的调解员至少勾选1人（负责分案结果审核监督），普通调解员至少勾选1人；否则不允许开始智能分案；
5. **分案边界**：智能分案算法仅在已勾选的调解员范围内进行案件分配。

**法院维度的分案规则配置**（每个法院独立配置）：三维度权重（案件数量默认50%/标的金额默认30%/案件类型默认20%）、人工审核开关（默认启用）、审核超时时间（默认24小时，超时默认采用智能分案结果）、分案结果通知渠道（系统内通知/飞书消息/短信，可多选）。**已取消调解员忙碌值设计**，不再根据当前案件数量判断忙碌状态。

### 5.5 双看板流程（信息看板重构）

平台设置两个差异化看板：**调解驾驶舱**（系统管理员，监控驾驶舱：全平台核心指标7卡片、待处理事项、全平台预警、各法院对比表格、调解员效能排行Top10、近6个月案件趋势、重要操作动态时间线）与**调解工作台**（主管标识调解员，工作台：多法院按钮切换、今日概览4卡片、关注事项、预警信息、调解员排行Top5、案件类型分布、案件动态时间线）。数据每5分钟自动刷新、支持手动刷新、重要预警实时推送。

> 两看板的页面结构、模块详设与对比表详见《03》调解驾驶舱章节、《04》调解工作台章节、《07》BI可视化面板设计。

### 5.6 数据概览多法院看板切换

数据概览页支持平台总览与各法院单独看板灵活切换（下拉选择器+Tab切换；平台总览默认仅系统管理员；主管标识调解员默认显示管辖法院数据并在管辖范围内切换；总览特有模块：法院分布饼图、法院数据对比表格、调解员效能排行Top10、调解组织效能对比）。详见《03》数据概览章节。

## 七、字段字典表格

### 7.1 调解员标签体系

**标签分类**：

1. **等级标签**（互斥）：首席调解员、高级调解员、中级调解员、初级调解员；
2. **专业领域标签**（可多选）：民间借贷专家、合同纠纷专家、劳动争议专家、婚姻家庭专家、交通事故专家、知识产权专家、其他；
3. **收益系数标签**（互斥，直接影响收益核算）：A类调解员（1.2）、B类调解员（1.0）、C类调解员（0.8）、实习调解员（0.5）；
4. **状态标签**（系统自动维护）：在职、休假、离职、暂停执业。

### 7.2 费用三要素与提成公式（主口径）

> **【2026-09-16 规则校准】**：会议确认提成核算的唯一基准为实收调解费总和；标的额仅用于前期业务风险判断，不参与提成计算（但参与应收调解费计算）。详见《00》第十五章。

```
① 标的额：案件纠纷合同金额（案件自带；仅用于业务风险判断与调解费计算，不参与提成计算）
② 应收调解费 = 诉讼费 × 法院比例
   · 诉讼费 = 按全国统一标的额分段累计标准（《诉讼费用交纳办法》）计算
   · 法院比例 = 该法院预置比例（40%–50%，逐法院配置，预置于应收字段）
③ 实收调解费 = 实际向当事人收取（允许打折/优惠），由调解员（含/不含主管标识）逐笔自行录入
④ 退费 = 实际退回当事人，由调解员（含/不含主管标识）逐笔自行录入
⑤ 调解员提成 = 基于实收调解费总和按提成档位规则核算（原值为实收调解费总和；档位细则待业务补充）
```

- 应收由系统算、实收/退费由人员录入并逐笔留痕（凭证、方式、时间、折让/退费原因、录入人），支持分次收、多次退；
- 退费规则的严谨性校验结果与优化方案需同步至系统配置，避免调解员自主调整费用影响发放；
- 提成核算原值固定为**实收调解费总和**，具体档位/阶梯算法待业务方补充（见第13章待确认清单第6项）；
- 单笔费用跨档位导致的提成差额属正常绩效差异，不做特殊规则调整（财务已重新校验确认无逻辑错误）；
- 等级收益系数字段保留为**扩展预留**：是否在提成基础上再乘系数，待业务确认后启用，当前不参与计算；
- 调解主管激励规则：基于调解提成同构框架，具体数值待业务方补充（见第13章待确认清单第9项）。

### 7.3 月度费用报表要素

按 调解员 × 法院 × 调解组织 汇总：案件数、标的、应收、实收、退费、提成。数据表（行=调解员）可排序/导出；行展开逐案明细（标的、应收、实收、退费、提成、费用状态），再下钻看每笔流水。

### 7.4 权限分配配置项

角色分配（两值）、主管标识（勾选，留痕）、管辖范围（带标识者，法院可多选）、可参与法院（调解员，可多选）、调解组织归属（可多选）、调解员标签（等级/专业领域/收益系数）、数据权限。

> 平台全量业务实体的字段级定义详见附件《05_数据库设计文档》；入驻法院项目与基础数据字段见第5.3节与本章上文。

## 九、校验&异常场景

| 场景       | 校验/处理规则                                             |
| -------- | --------------------------------------------------- |
| 无已通过绑定   | 登录进入受限引导页，业务列表/看板为空态，只能申请绑定或查看审核状态；接口返回无有效绑定提示      |

| 分案人员勾选   | 带主管标识与普通调解员各至少勾选1人，否则不允许开始智能分案                      |
| 忙碌值      | 已取消忙碌值设计：分案不按案件数量判断忙碌，无忙碌阈值                         |
| 权限越界     | 主管/调解员访问无权限功能（分案、系统设置、操作日志、权限分配等）时拦截；前端隐藏菜单不能替代后端过滤 |
| 提成口径     | 固定=实收−退费；等级系数默认不乘（预留）                               |
| 退费校验     | 退费不超过实收（详见《03》财务配置）                                 |
| 主管标识调整   | 留痕、即时生效；本人不可自改                                      |
| 入驻项目重复提交 | 被拒后可修改重新提交；审核期间不可重复提交同一法院                           |
| 申请返回     | 必填理由；审核中防重复发起；驳回后可再次发起；同意后案件退出智能分案体系                |
